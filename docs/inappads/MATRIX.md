# In-app ad module matrix

Generated by `tools/generate-inappads-evidence.py` from the catalogue, each module's Makefile, filter plist and Module.m, and `evidence.json`. Do not edit by hand. One shared dylib (`MYBInAppAds.dylib`) now carries every module.

Reading the columns: **Built** = the module is a Makefile subproject and a tweak of its own; **Packaged** = its dylib and filter plist are checked in the package by CI (`tests/verify-package.py`, which also needs arm64 and arm64e); **Visible** = the app appears in Settings > In-App Ad Blocking when installed, and its status is listed. **Interface source** says where the class and selector names come from. It is evidence that the interface exists, **not** evidence that ads are removed in a given app version. **Device-verified** is empty for every module: none has been run on a device.

## Notes per module

- **YouTube**: Now also filters ad entries inserted, replaced or seeded through the section view model. Hooks corroborated by a maintained YouTube ad tweak. YouTube app version on a device: not recorded.
- **Instagram**: Unchanged in this release: ad handling only. The Reel comment shopping carousel that the lead tweak removes with its ad switch is deliberately NOT removed, because nothing marks it as an advertisement. Hooks corroborated by a maintained Instagram tweak. Instagram app version on a device: not recorded.
- **TikTok**: Douyin (com.ss.iphone.ugc.Aweme and the lite app) is now covered by this same module: DYYY (huami, MIT; names only) classifies an AWEAwemeModel as an ad through checkIsAd, isHardAdModel, isHardAd or isAds, so those three selectors were added to the classifier (each is consulted only if the model responds to it). The two initialiser hooks are unchanged and whether they act on Douyin models the same way is unconfirmed. Reviewed against Selandros/TikTokClean at 0f898e0 (2026-07-04, MIT): the module already uses its ad classification (isAds, isAdsOrPseudoAds, adInfo, adOrPseudoAdModel, adType) and both model initialisers; no ad-metadata gap was found. Not adopted: its LIVE removal (excluded), its auto-skip of an ad that is already on screen (scrolling the feed is not ad removal), downloads and auto-scroll. The older 2023 BHTikTok source is kept as a second reference. Upstream tested 45.7.0 and 45.8.0; our own device test: none.
- **SoundCloud**: Independent corroboration found this session: a 2020 SoundCloud class dump (not the GPL tweak) declares the AdsRequestPermitting protocol with shouldRequestAds, matching hook 1 in interface; the other two hooks have no independent evidence. Also refuses soundcloud.com/ads and promoted.soundcloud.com requests (path level, as the lead tweak does). Swift-mangled names are version specific; corroborated by a maintained SoundCloud tweak. App version on a device: not recorded.
- **Reddit**: Scope note: the Home experiment override (removing ios_home_feed_defer_query) is NOT adopted. It changes how Home loads for every user, and it was not shown to be needed for ad removal or to leave existing feed behaviour unchanged. Known limit: ads in the streamed first Home page that the app requests without a completion handler may remain. Reviewed against and101/RedditFilter at e1b597f (2026-11-13, MIT). Newly adopted: comment-page ads in the object-wrapped adPosts form. Not adopted: the Home experiment override, keyword, NSFW, awards, scores, recommended-post and UI features, and its cached experiment file edit (it writes into the app group container). Reddit works on the GraphQL response shape, not on app classes: the module removes entries carrying an ad payload from the data-task response. Public Reddit ad-removal scripts for proxy tools filter the same AdPost/adPayload shape, which is shape evidence only. No class-level source.
- **YouTube Music**: Reviewed against dayanch96/YTMusicUltimate Source/RemoveAds.x at e5530b1 (2026-08-19, GPL-3.0; read as a lead, no code copied): adopted isMonetized (also declared in both YouTube Music class dumps). Not adopted: isCuepointAdsEnabled and paidContentOverlay (not in the YouTube Music dumps; the overlay is a paid-promotion disclosure), isDAIEnabledPlayback (answer is flipped to YES, semantics unverified), and the spam-signal dictionaries (ad-request attestation, unverified effects). Playback, subscription and download changes are excluded. Only the four interfaces found in a published YouTube Music class dump (version 3.59, an old release) are hooked. Ad-slot and Impl-decorator hooks exist only in YouTube app sources and are deliberately NOT used. Whether these three remove audio ads in a current YouTube Music version is unproven.
- **X**: The same selectors and the same promoted tests a maintained X tweak (BHTwitter) uses, now four: promoted rows and trends, the promoted post card, and the dynamic-video-ad capability. The tweak does not state an X version. Not run on a device.
- **Messenger**: Reviewed against FlowReconstructed at 83e062c (unchanged since the earlier review) and SNMessenger at 3917697 (2025-07-31, MIT). Adopted from SNMessenger, as interface evidence written independently: advertisement story buckets (bucketType 1) are dropped, with the added index paths of the update kept consistent. Not adopted: its inbox ad-unit fetcher returning nil (how its callers handle a nil answer is unverified, so a crash or a stuck chat list cannot be ruled out without a device) and its _unitsState row-position route (instance-variable based, version specific). Same classes, selector and ad key as one maintained tweak (Flow); a second tweak (SNMessenger, Messenger 458+) finds the ad row by a different route, so which representation a current Messenger uses is unknown. Not run on a device.
- **Facebook**: Interfaces and decisions follow Facebook-Plus (GPL-3.0) and, for Marketplace, MarketplaceAdBlock (no licence file), both pinned above; upstream tested Facebook 570/574/578 and 584.0.0. The feed hook reads the sponsored classification at model init as upstream does; whether a given Facebook build classifies later is unchecked (opt-in discovery logs it). Not run on a device.
- **Amazon Shopping**: Hides only the two confirmed data-attribute markers with a bundled WebKit content rule list. The other markers (isSponsoredProduct, puis-sponsored-label-text, sponsored-products-detail-mobile) are counted by opt-in discovery, never hidden. The amznkiller list could not be read or pinned. Native cells are not covered. Bundle id com.amazon.Amazon is unverified on a device. Not run on a device.
- **Threads**: Six rules from the class and selector names ThreadsPulse publishes, covering the ad request, sponsored items and their feed insertion. Names only; its licence is not stated, so no code is used. Threads is a Swift app, so every class is a mangled name and each rule stays off if the name changed. Not run on a device.
- **Gmail**: Four rules giving inbox advertisement rows zero height, from the AdsCell and GBTAdsCellImpl names in a 2021 Gmail tweak. Those classes may no longer exist in current Gmail; if none are found the module reports no hooks found. Not run on a device.
- **Douban**: Five rules for the launch ad and the commercial and review-list ad requests, from a 2024 tweak (names only, MIT). Not adopted: the launch-prompt hook that also hides the launch doodle (not ad-only), an initialiser answering nil, and the unrelated API-version change. Class names may have changed in current Douban; if none are found the module reports no hooks found. Not run on a device.
- **QQ Music**: One rule for the launch ad, from a 2024 tweak (names only, MIT). The high-quality-audio unlock hooks in the same project are not advertising and are not used. Not run on a device.
- **Sogou Input**: Four rules for the launch ad and native ad cells, from a 2024 tweak (names only, MIT). The jailbreak-detection and purchase-flag changes are not advertising and are not used; the ad-cell model rewrite edits an argument, which the rule table cannot express, so it is not adopted. Not run on a device.
- **WeChat**: Eleven rules for the launch ad and Moments ad data and requests, from a 2023 tweak (names only, MIT; WeChat has changed since, and each rule stays off if its signature differs). Not adopted: jailbreak-detection changes, the article-ad request rewrite (a network rewrite), the Moments canvas-cell hooks and unrelated hooks. Not run on a device.
- **Bilibili**: Two hooks, ad-only: the home feed response (commercial cm_v1/cm_v2 cards, cm_double cards carrying ad_info, banner items flagged is_ad) and the three search ad card types (video_ad, picture_ad, brand_ad_giant), from cxz/BiliBiliTweak at 9062479 and BiliBiliMApp at 37b8d31 (MIT; names and card types only, written independently). Not adopted, because they are not advertising decisions: its popup and rating-prompt removal, banner removal, live-room panels, appointment buttons, related-game and goods cards, special_s cards, search default-word blanking, playback and account changes. Not run on a device.
- **App Store**: Discovery only: no hook is installed and nothing is blocked. No published tweak or class dump for the App Store sponsored placements on iOS 16 was found, so there is nothing established to hook. Opt-in collection of class, selector and view-type names (docs/inappads/DISCOVERY.md) is how the placements will be identified. Not run on a device.

## Apps not implemented

Spotify, Twitch, LinkedIn, Pinterest, Snapchat, Tumblr, Pandora, Deezer and WhatsApp have no module: no runtime interface for them could be checked against a source in this work, and a guessed class name that does nothing is not a feature.

## Coverage (derived from the catalogue and the build)

- **Apps with ad-removal hooks: 17** (youtube, instagram, tiktok, soundcloud, reddit, youtubemusic, x, messenger, facebook, amazon, threads, gmail, douban, qqmusic, sogou, wechat, bilibili). Each has its own control and a rule/hook list in the matrix above; none is device-verified.
- **Discovery-only targets: 1** (appstore). They collect interface names during a session and block nothing.
- **Shared SDK support:** 16 entry points across 6 SDK families (Google Mobile Ads, LevelPlay, Meta Audience Network, Mintegral, Unity Ads, Vungle / Liftoff), applied only to apps the person selects under Ad Network Blocking. It is not a per-app module and adds nothing to the app counts above.
- **SDKs not covered: 2** (AppLovin MAX, Google IMA); the specific blocker for each is in `SDK-AUDIT.md`.
