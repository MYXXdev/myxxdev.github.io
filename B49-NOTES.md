# MYbloXX B49

The preferences interface has a new graphite design with quieter lavender accents, one spacing/type system, constrained custom cells, vertically centered icons and accessories, compact headers and custom keyboard-aware sheets. Native stock labels and accessory positioning are not overlaid or hidden. The canonical logo vector is unchanged; icon assets have higher-resolution variants, clear transparent corners, matching 25% radii and no outline/shadow.

Rules Updates is now Automatic Updates. Manual checks show Checking Updates, then MYbloXX Is Up to Date or MYbloXX Updated as appropriate. Backup & Restore has a saved-backup summary and three actions: Back Up Now, Restore Backup, Export Backup. Export produces one complete settings backup; both existing saved-backup and file-picker restore paths remain available inside Restore Backup.

App Control has no master toggle or tuning pages. Every app has one switch. The engine is always available and uses a fixed 100x acceleration request, video fast-forwarding, rushed countdowns, accelerated clocks and ad-SDK jailbreak compatibility. Removed code includes force-inline overrides, all-native-video acceleration and SDK ad-blocking stubs. Old master/tuning preferences are ignored and removed on upgrade, preserving app choices. Existing backups restore their app choices without reintroducing tuning. Uninstall uses a separate internal gate, preserving B48 cleanup behavior.

100x is a request, not a guarantee that every decoder or ad network will honor it. Web players that reject or clamp the request use a supported lower rate without recursive rate-change loops. Timer/clock acceleration remains enabled while a video is present. Existing tracked web views are updated when the app selection or foreground state changes; disabling acceleration restores normal clock/timer behavior and the original video rate. Native video acceleration remains limited to recognized ad view controllers. No completion/reward events are forged.

Validation includes native state transitions, preference migration and uninstall checks, JavaScript acceleration/fallback/reversion checks, UIKit interaction checks, actual Simulator renders of the production controllers with fixture state on an iPhone 14 Pro Max, player acceptance probes, a complete arm64/arm64e RootHide build and Apple dyld validation. Simulator previews exercise the actual view classes, not HTML approximations. Device-specific rendering and ad-SDK outcomes still require device testing.
